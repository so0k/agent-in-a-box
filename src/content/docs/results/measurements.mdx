This page holds every number the workshop quotes: tokens, cost, turns and time for each act and task, and the build of Box each was measured on. After it you will know what each set-up costs the developer, how much of that is the tool list, and how far the numbers can be compared. The story needs it last because the acts traded control against cost, and this is the cost side, measured.

<Pieces stage={5} />

The picture is the final one. The numbers below belong to its different paths: the token-scope act without the box, the next four acts through the vendor's MCP server, and the request-rules act through the local exec proxy.

## How to read these numbers

- **One run per cell.** Each row is one run, with model `claude-sonnet-5-5`, a plain task and no adversarial prompting. A second run of the same task can differ; where a repeat exists, it is shown.
- **Claude Code's own figures.** Turns, tokens and cost are what Claude Code reported at the end of the run, in its `result` event. Box's records hold no token or byte figures.
- **Input tokens** are all kinds added: uncached, cache write and cache read. The three parts are shown in brackets.
- **Time** is two numbers: Claude Code's own duration, and the wall time of the whole command.
- **Tool loading** says what the model was given. "Code mode" is the vendor's server with a handful of tools, run with `--tools ""`, so Claude Code's tool search was off. "Per-endpoint" is the vendor's 3,053 tools with tool search on (`--tools ToolSearch`), so the model receives only the tool names and loads a definition when it needs one. "Exec proxy" is the local server's two tools, tool search off.
- **Builds.** The workshop's steps use **pkg-fix**, a local build that prints `box 0.1.0`: public strands-agents/box main `c70fec5` plus an earlier round of a fix for MCP tool schemas that is not in upstream Box, built 2026-11-21 as an uncommitted diff. The fork branch `bugfix/mcp-shared-definitions-workshop` holds a later review round of the same fix on the same commit; a build from it is not byte-identical to pkg-fix, and the acts were not run again on it. Other local builds (pkg, pkg-main) and the installed release box 0.1.8 appear in separate groups. [Builds and gaps](/results/builds-and-gaps/) says what each build is.
- **Do not compare across groups as if only Box changed.** The groups also differ in Claude Code version (2.1.325, 2.1.326, 2.1.330) and in the policy files: the pkg-fix runs of the deny-execute and request-rules acts used the files you write in this workshop; the other runs used policies generated by the author's kit (now in the `kit/` folder of [box-exec-proxy](https://github.com/so0k/box-exec-proxy)), so their refusals name other rule ids.
- **Outcome "logs returned"** means log lines came back. In these runs the last hour of the Worker's logs held only two request lines; the attendee events with email addresses were older. An email came back in one run: the token-scope act with a 24-hour window (redacted in the evidence).

Sources: the result files of each run, in the author's measurement notes (not published), and Claude Code's own result figures of the runs made while writing and verifying this workshop. Every number on this page was copied from one of those; none is estimated.

## Where the tokens go: the tool list

Most of the tool-allowlist act's cost is the tool list. These figures come from Anthropic's token-counting endpoint for `claude-sonnet-5-5`, with the tools named as Claude Code names them. They were measured on 2026-11-14, when the per-endpoint catalog had 11 tools fewer than the 3,053 it had on 2026-11-21, and the larger list was not counted again. The numbers differ by more than a thousand times, so they are a table, not a chart.

| Tool list | Tokens | How measured |
|---|---|---|
| Exec proxy, 2 tools | about 1,500 | an estimate: 6,071 bytes divided by four, not counted |
| Vendor code mode, 4 tools | 3,510 | counted |
| Vendor per-endpoint, names only (what tool search sends) | 75,349 | counted, on the list of 2026-11-14 |
| Vendor per-endpoint, every definition | 2,382,210 | counted, on the list of 2026-11-14 |

What a run actually sent, measured: the first model request of the request-rules act was 2,263 input tokens in all (box 0.1.8 run). The first request of the tool-allowlist act, with tool search on, was about 78,600 input tokens, and each later turn read those names from the cache again, which is why every tool-allowlist run came to about 240,000.

## Waiting for the tool list

A free check (an invalid model key, so nothing is billed) shows how long Claude Code waits before it has its tools. Measured on the newer builds with Claude Code 2.1.330:

| What started | Build | MCP status, tools | Wait for the tool list | Wall |
|---|---|---|---|---|
| Vendor code mode | pkg, pkg-main | connected, 5 | 0.2 s | 3 to 4 s |
| Exec proxy | pkg, pkg-main | connected, 2 | not applicable | 3 to 4 s |
| Exec proxy, the workshop's profile | pkg-fix | connected, 2 | not applicable | 3 s |
| Per-endpoint, Claude Code's default timeout | pkg | pending, 0 | Claude Code gave up after 29.9 s | 63 s |
| Per-endpoint, `MCP_TIMEOUT` raised | pkg-fix | connected, 3,053 | 65.9 s | 70 s |
| Per-endpoint, the workshop's allow-list | pkg-fix | connected, 3,053 | 70.4 s | 73 s |
| Per-endpoint, allow-list and argument rule | pkg-fix | connected, 3,053 | 70.8 s | 75 s |
| Per-endpoint, with a rule for a tool the catalog does not have | pkg-fix | connected, 3,053 | 162.8 s | 167 s |

Across every connected per-endpoint check and run on the newer builds the staging wait was 61.5 to 66.2 seconds, apart from the workshop's own checks above. The 162.8 seconds was one run; whether the rule that never loaded caused the extra time was not checked. On box 0.1.8 and 0.1.11 the wait was 1.2 to 1.5 seconds, because those builds refused the catalog at once and staged nothing.

## What the numbers mean for each seat

<Seat who="security">

- Control did not have to cost money. The request-rules act's logs run, refused at the gateway, cost USD 0.0275 on pkg-fix; the uncontrolled token-scope run, without a box, cost USD 0.0318. Different set-ups and Claude Code versions, so read it as the same order of size, not as a saving.
- Refusing `execute` by name was cheap too (USD 0.0090 for the allowed task), but it refused the harmless task.
- Per-operation control through the vendor's catalog cost 7 to 14 times as much per run as the token-scope or request-rules act (measured on box 0.1.8), and on the newer builds a minute of waiting, on every run, whether or not anything was refused.
- These are single runs of plain tasks. They say nothing about a model that tries to get around a rule.

</Seat>
<Seat who="developer">

- The request-rules act is the cheapest working set-up measured: 4,089 input tokens and USD 0.0140 for the allowed task on pkg-fix, in 2 turns and 9 seconds.
- The per-endpoint catalog sends about 75,000 tokens of tool names on every request, even with tool search, and waits about a minute before the first turn on the newer builds. Turning tool search off does not help: the request is too large for the model.
- A refusal costs turns. The deny-execute act's logs task spent 6 turns and 75,732 input tokens searching before it reached the refused `execute`; the request-rules act's spent 4 turns and 17,302.

</Seat>

## What to remember

- The workshop's steps use pkg-fix; the token-scope, opaque-execute and tool-allowlist acts were measured on other builds, and every number here says which.
- Code mode and the exec proxy cost a few thousand to a few tens of thousands of input tokens a run; the per-endpoint catalog about 240,000.
- Most of the per-endpoint cost is the tool names, sent on every request.
- On the newer builds the per-endpoint catalog adds a wait of about a minute before the agent has its tools.
