## The builds

All the local builds below are unreleased and carry only the linker's ad-hoc signature. They report `box 0.1.0`: local builds do not stamp a version, so the version string says nothing about what is inside. Each ships `box`, the two helper programs `strands-box-sock-alias` and `strands-box-contain-trampoline`, and a `resources/` folder beside the binary (the shipped packs, starters, policy starters and the agent guide). Toolchain: rustc 1.98.1, aarch64-apple-darwin.

| Build | What it is | What it contains | Used for |
|---|---|---|---|
| **pkg-fix (the workshop's build)** | Public `strands-agents/box` main at `c70fec5` (#572) plus the `$defs` fix, built 2026-11-21 from an earlier round of the fix, as an uncommitted diff | The fix for three `$defs` constructs that stopped schema generation (below, gap 1). No other patch. `Cargo.lock` unchanged (`--locked` held) | Every command on this site; the curriculum's proofs (2026-11-22) |
| pkg-main | Public main `c70fec5` plus an earlier local patch for the same problem (`core-01`) | The CLI as now imported into the Core repository, with #505 | Measurements of 2026-11-21 |
| pkg | A pre-release build of the older CLI line, with Box Core moved to `217c860` by a local path override, plus `core-01` | Depends on two local uncommitted patches; built without `--locked` | Most newer-CLI measurements of 2026-11-21 |
| box 0.1.11 | A release of the older CLI line | Same per-endpoint refusal as 0.1.8 | Two tool-allowlist result files only |
| box 0.1.8 | The installed release of the older CLI line (`~/.box` home) | No `BOX_HOME`; refuses the real per-endpoint catalog | Measurements of 2026-11-14 |

The workshop teaches only the newer CLI's form (profiles under `$BOX_HOME`, packs named `@box/<name>`, `[project] access`). Profiles written for 0.1.8 do not carry over.

### Building pkg-fix yourself

[Requirements](/start/requirements/) names the build as a requirement. In outline: clone the branch `bugfix/mcp-shared-definitions-workshop` of the fork `so0k/box` (upstream commit `c70fec5` plus a later round of the fix than the uncommitted diff pkg-fix was built from, so not byte-identical to pkg-fix; whether it behaves the same in the acts was not checked), build `box`, `strands-box-sock-alias` and `strands-box-contain-trampoline` with `cargo build --release --locked`, and copy the binaries and `resources/` into one folder. The build steps are derived from the build record, and none of these steps, the clone included, was **run** for this site. The same fix on current upstream main is the branch `bugfix/mcp-shared-definitions`. Upstream release v0.3.0 and upstream main still have the bug as of 2026-11-24, so the per-endpoint catalog act needs the fork build. The site's measurements were not repeated on v0.3.0 or on current main.

## Gaps between this workshop and a released Box

Status as read on 2026-11-21 and 2026-11-22 in the public strands-agents repositories (issues, pull requests and releases) and in the author's measurement notes (not published). Anything newer (merged, released, answered) was not checked, except where a row says 2026-11-24.

### Gaps that need a change in Box

| # | Gap | Status | What would close it |
|---|---|---|---|
| 1 | **One tool can refuse the whole MCP server.** Three `$defs` constructs stop schema generation: a definition name that is not a Cedar identifier (such as `iam_create-account`), a definition that is an array of objects, and a definition that refers to itself. Of the 3,053 per-endpoint tools, 441 have at least one. Box then refuses every call to the server with `the MCP tool catalog is not accepted`. | **Not upstream.** The fix is on the branch `bugfix/mcp-shared-definitions-workshop` of the fork `so0k/box`, on top of public main `c70fec5`, and on the branch `bugfix/mcp-shared-definitions` on current upstream main. Upstream release v0.3.0 and upstream main still have the bug as of 2026-11-24. An upstream issue and pull request for this fix were drafted but **not filed** (as read 2026-11-22), so this fix is not merged and not released. The earlier argument-name problem (#497) was fixed by #505, merged 2026-11-20; upstream release v0.3.0 contains #505 (checked 2026-11-24). | File the issue and pull request; review and merge; a release that contains it. |
| 2 | **The tool list is held while Box stages the catalog.** Box types all 3,053 tools before it releases `tools/list`: 61.5 to 66.2 s measured. Claude Code's MCP start timeout defaults to 30 s, so it started with 0 Cloudflare tools, and Box printed no warning. | No upstream issue. | Staging off the request path, much cheaper staging, or a warning and documentation. The workshop sets `MCP_TIMEOUT = "300000"` in the profile. |
| 3 | **No per-tool fallback.** One malformed tool fails the whole server and every per-tool rule with it. The fix removes the three known causes; others listed in the notes still refuse the server. | Open design point. | Leave out a tool Box cannot type, on its own, and keep the rest. |
| 4 | **`cedar-for-agents` PR #267** would accept non-identifier names in the schema generator. It addresses only cause 1 of gap 1. | Open, no reviews (as read 2026-11-21); not in release 0.8.0. Box pins the generator at 0.6.1. | If it ships, part of the Box fix can go and generated type names change. |
| 5 | **Open upstream PR #465** would key a remote catalog by address, path, query and session, so `?codemode=false` becomes part of the key. | Open, conflicted, review required (as read 2026-11-21). | No change needed in the workshop today. |
| 6 | **No released CLI with the fix.** The CLI moved into the Core repository. Its release v0.3.0 (2026-11-23) still has the bug of gap 1. | Open as of 2026-11-24. | A release; until then, a local build. |

### Limits and design facts the workshop works around

| # | Fact | Status | How the workshop handles it |
|---|---|---|---|
| 7 | Box refuses a run whose broker socket path is over 103 bytes. The path is the Box home plus 38 bytes (derived), so `BOX_HOME` may be at most 65 bytes. The CLI does not check this up front. | Documented limit. | `BOX_HOME="$HOME/box-ws"`, short for any normal user name. |
| 8 | Tool names cost tokens: 3,053 names are sent on every request even with tool search (75,349 tokens measured on the list of 2026-11-14, 11 names fewer); a per-endpoint run cost 7.4 to 13.9 times the token-scope or request-rules act. With tool search off the request is refused (about 2.2 million tokens against a 1,000,000 limit). | Inherent to per-endpoint mode and the client, not a Box defect. | Tool search on in Part 4; the local exec proxy in Part 5. |
| 9 | A tool-name allow-list must name every tool a model might pick: in the tool-allowlist act Claude chose `workers_list`, which the list did not name. | Design gap of the allow-list, not a Box bug. | The tool-allowlist steering sentence names the one tool to use. |
| 10 | The per-endpoint catalog is 6,540,316 bytes, 78% of Box's 8 MiB cap per list. It grew by 11 tools, to 3,053, in a week. | Limit, not filed. | None needed today. |
| 11 | Usage telemetry is on by default in the newer CLI. `box telemetry off` writes a file outside `BOX_HOME`. | By design, documented. | `BOX_TELEMETRY=0` in the shell. |
| 12 | The vendor's `execute` hides the API call from Box (the opaque-execute act). | By design: the reason for the deny-execute and request-rules acts. | The request-rules act. |
| 13 | Argument typing edge cases (an argument of unknown type, objects without properties, date formats) are not shown for rules on arguments. | Not tested. | Rules on typed arguments only, such as `path.account_id`. |
| 14 | Policy-writing traps: a rule naming actions of two namespaces must be split; a rule on an MCP tool's response loads but never matches (issue #396); a per-tool `permit` that does not match falls back to the server's permit. | Known behaviour (#396 open). | Part 4 writes `forbid` rules. |
| 15 | Interactive mode was checked only up to its first screen; it has no dollar cap. | Not checked further. | Measured steps are headless with `--max-turns` and `--max-budget-usd`. |

## What's next: code mode in the agent harness

In the request-rules act the exec proxy, a small local MCP server, runs the agent's script inside the box, so each API request crosses Box's egress gateway. Agent harnesses are starting to run such scripts themselves. As read 2026-11-24 in their docs:

- **Claude Code** has Code Mode, experimental and off by default, from v2.1.323, turned on with `CLAUDE_CODE_EXPERIMENTAL_CODE_MODE=1`. "Claude writes JavaScript that makes the tool calls, and Claude Code runs that code in your session." Claude Code's own sandbox setting, which is separate from Box, covers only the shell commands the code runs.
- **OpenCode** has a tool: "`execute` runs JavaScript in Code Mode so the agent can call and combine tools from the catalog." MCP servers are reached through `execute` unless a server sets `codemode: false`. The runtime "provides `fetch` for HTTP requests; everything else goes through tools in its catalog."

This is the idea of the request-rules act: the script and its requests run on the developer's side, so a box around the agent could see each request. For isolating the script, Claude Code's docs say: "run Claude Code in a container or virtual machine." In this workshop that is the box's job.

If a harness does this inside a box, the exec proxy and its registration (`[mcp.exec-proxy]`, `exec-proxy.json`) could go, and the rules on each request would stay: less to ship, same story.

What is not known:

- Neither feature was run for this workshop, inside a box or outside.
- Box ships no pack for OpenCode. As read 2026-11-24, release v0.3.0 has agent packs for Claude Code, Codex, Kiro and Pi (`claude`, `codex`, `kiro`, `pi`). Running OpenCode in a box would need a hand-written profile, which was not tried. An open draft pull request in the Box repository, #418, works on two things it says OpenCode needs on macOS.
- Whether Code Mode starts when Claude Code's model traffic goes through Box's egress gateway (Box points the agent at it with `HTTPS_PROXY`). Its docs say "You can't use Code Mode through a gateway", nor through some cloud platforms.
- Claude Code's page describes code that makes tool calls, not HTTP requests of its own. Code Mode also needs "an interactive `claude` session in a terminal"; this workshop's measured runs are headless.
- Whether the scripts' requests pass through the box's gateway the way the exec proxy's do.

## What to remember

- Every command here ran on pkg-fix, a local build of public main `c70fec5` plus a fix that is not yet filed upstream.
- The fix that makes Part 4 work is not upstream, and an issue and a pull request for it are drafted, not filed. The fork branch `bugfix/mcp-shared-definitions-workshop` holds a later review round of it on the same commit as pkg-fix: a build from the branch is not byte-identical to pkg-fix, and the acts were not run again on it.
- `box 0.1.0` is an unstamped local version, not a release.
- The CLI gaps are mostly about seeing: live decisions, readable records, and checking a rule before a run.
