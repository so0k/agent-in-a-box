This page puts the six acts side by side. After it you will be able to say, for each set-up, what the security engineer's policy could see and decide, what the developer paid for it, and whether the developer's task got done. It closes the story the workshop told: a team that runs the workshop progress tracker and leaderboard, a developer who wants a coding agent to help operate it, and a security engineer who writes the constraints.

## The final picture

<Pieces stage={5} />

Every piece the workshop added is on it: the box CLI and Box Core around Claude Code (Part 2), the contained filesystem view, the stand-in secrets and the egress gateway (Part 2), the MCP broker, the policy engine and the records (Part 2 and Part 3), the staged tool catalog of the per-endpoint mode (Part 4), and the local exec proxy inside the box (Part 5). The vendor's MCP server is still drawn, dashed, because acts b1 to b3-args used it.

## The six acts compared

The constraints were the same in every act: the agent may read what it needs to operate the app; it may not read the logs or the stored attendee data, and it may not deploy or delete. The two tasks were the same too: the allowed task (list the Workers and summarise the current deployment of `box-poc-workshop`) and the logs task (the last hour of the Worker's logs).

| Act | What the policy could see | What it could decide | Input tokens and cost per run | Developer's task done? |
|---|---|---|---|---|
| a, no box | Nothing. There is no box. | Nothing. Only the token's own permissions limit the agent. | allowed 3,981, USD 0.0160; logs 21,563, USD 0.0318 | Both done. The logs came back. |
| b1, vendor's server in a box | One `mcp:call` per tool call, such as `cloudflare/execute`. Not the script, not the API request. | Which tools of the server may be called. Nothing was refused in this act. | logs 100,197, USD 0.0778 (the allowed task was measured only on box 0.1.8: 3,954, USD 0.0114) | Both done. The logs came back, and Box saw only `permit execute`. |
| b2, `execute` refused by name | The same tool calls. | Refuse `execute` by name. | allowed 4,826, USD 0.0090; logs 75,732, USD 0.0729 | Neither. Control cost usefulness. |
| b3, one tool per operation | One tool name per API operation, from a catalog of 3,053. | An allow-list of six tool names. | allowed 241,478, USD 0.2278; logs 248,292, USD 0.2357 | Partly. The deployments were answered; the model picked `workers_list`, which is not on the list, so the Worker list was refused. The logs were refused. |
| b3-args, one tool on one account | The tool name and its typed arguments, such as `path.account_id`. | One tool on the workshop's account only. | 320,678, USD 0.2354 (a steering sentence, two calls) | Yes for the workshop's account; the call on another account was refused. |
| c, local exec proxy | Every API request the script sends: method, host, path. | Each request: two `GET`s permitted, everything else on `api.cloudflare.com` refused. | allowed 4,089, USD 0.0140; logs 17,302, USD 0.0275 | Allowed task done in one `execute`. The logs query was refused at the gateway, with the rule's name. |

Input tokens are all kinds added (uncached, cache write, cache read), as Claude Code reported them. One run per cell, model `claude-sonnet-5-5`. The builds differ by row, and so do the Claude Code versions: act a ran without a box (Claude Code 2.1.325, 2026-11-14); b1 and b3 on the local build called pkg; b2, b3-args and c on pkg-fix, the build the workshop's steps use (Claude Code 2.1.330 for all three newer-build rows). The [measurements](/results/measurements/) page has every number with its build. On the newer builds, each b3 and b3-args run also waited about a minute while Box staged the 3,053-tool catalog: 75 to 85 seconds of wall time, against 9 to 14 seconds for act c.

## What each seat takes home

<Seat who="security">

- A sandbox decides only what passes through it. While the vendor's `execute` ran the script on Cloudflare's side (act b1), the policy saw a tool name, and the logs came back.
- Refusing a tool by name is a blunt control: it stopped the harmless task too (act b2).
- Rules on tool names depend on the model picking a listed tool (act b3). Rules on typed arguments are precise, but they need the server's whole catalog staged and typed first (act b3-args).
- A rule on the API request itself, by method, host and path, does not depend on which tool or script sent it (act c). Write it as a `forbid ... unless` with exact paths, because a route's permit opens the whole host and a permit cannot narrow a permit.
- Two limits remain in every act: the policy decides requests, not what an allowed request returns (the deployer's email came back in act c), and the agent may hand the person a way round the control (in act b2 it wrote out a `curl` command to run outside the box).

</Seat>
<Seat who="developer">

- Code mode is cheap: a handful of tools, a few thousand input tokens for a simple task.
- One tool per operation cost about 240,000 input tokens and about USD 0.22 to 0.24 a run, and a wait of about a minute before the agent had its tools.
- The local exec proxy keeps code mode's cost and shape (act c: 4,089 input tokens, USD 0.0140, one `execute`), and a refusal comes back with a reason the agent can pass on.
- The price moves to the policy file: every new read the team needs is a line the security engineer adds.

</Seat>

## What to try next

None of these was run for the workshop: each is marked not checked.

- **Widen the read-only set.** The story allows reading a Worker's settings and versions. Add their exact `GET` paths to `operate_requests_only` and ask the agent for the bindings of `box-poc-workshop`. Not checked.
- **Ask for attendee data.** Ask the agent for the rows of the D1 `sessions` table. The SQL query is a `POST` that is not on the list, so `operate_requests_only` should refuse it. Not checked. Do not ask it to deploy or delete: if a rule were wrong, the request would reach the real app.
- **Fix the b3 allow-list.** Add `workers_list` and `workers_get` to `operate-tools.dw` and run act b3's allowed task without the steering sentence. Not checked.
- **Record a tool call's arguments.** Box can record the arguments and outputs of MCP tool calls to a declared telemetry target (Box docs, `telemetry.md`). In this story those records could hold attendee data in clear text, so decide first where they would go. Not checked.
- **Your own app.** Replace the account ID, the Worker name and the two paths with your own, and keep the shape: a route, a `forbid ... unless` with exact paths, a second rule that gives the most sensitive refusal its reason.

## What to remember

- The question for every set-up is the same: where does the API request happen, and does it pass Box on the way?
- Acts a and b1 got both tasks done, and the logs came back. Acts b2 to b3-args got control at a cost in usefulness or tokens.
- Act c gave both seats what they asked for, with the remaining limits named.
