This guided workshop explains how to sandbox your AI coding agent. It does so by solving one problem in stages, and by looking at every stage from different perspectives. On this page we go through the problem, who the workshop is for, and how every piece fits together.

## The problem

<Steps>
1. A developer wants [Claude Code](https://claude.com/product/claude-code), a coding agent, to help operate a small demo app that runs on [Cloudflare Workers](https://developers.cloudflare.com/workers/).
2. The agent reaches Cloudflare through an [MCP server](https://modelcontextprotocol.io/): a program that provides the agent tools it can call.
3. [Cloudflare's own MCP server](https://github.com/cloudflare/mcp) offers one generic tool, `execute`, that runs a script against __the whole Cloudflare API__.
4. A security engineer must be able to __allow or refuse each API operation__,
   
   in the case of our sample app: the logs and database hold people's names and email addresses!
5. We put the agent in a sandbox with [Strands Box](https://strandsagents.com/box/) and find out, step by step, where a policy can be applied and what each choice costs.
</Steps>

<Aside type="note">
A **sandbox** is a boundary around a program that decides what it may read, write, run and reach on the network. **Strands Box** (Box for short) is an open source sandbox engine for AI agents. You drive it with the **box CLI**, the `box` command.
</Aside>

## The Perspectives

Every stage is told from the perspective of a Developer and a Security Engineer. This is presented on every concept and act page as shown here.

<Seat who="security">

You decide what the agent may do. On each page you ask: what can the policy see, what can it decide, and what does it write down so that I can check later?

</Seat>
<Seat who="developer">

You want the agent to get work done. On each page you ask: what can the agent still do, how many tokens does it spend, and how much friction does the set-up add?

</Seat>

The site is for people who want to understand the moving parts and the trade-offs. Every command and every setting is explained: what it does, why it is chosen here, what the alternative would do, and where to read more.

## Your takeaways

- **What is Box**: Box contains the agent's files, its network, its secrets and its tools. We learn which part of Box enforces each.
- **Writing Profiles and Policies**: How a Box profile and a policy file are built up.
- **The ingredients**: What Box can see of an MCP tool call, and why a generic `execute` remote tool is hard to secure.
- **Policy design**: Three ways to put a decision on each Cloudflare operation (refuse the tool, one tool per operation, or decide each HTTP request) and how it impacts the developer.
- **How to Audit**: Where Box's records of decisions live, and how to read them with the box CLI.
- **Gaps and What's next**: Which parts of this set-up are local builds or proposals, and what a released Box still lacks.

### Three types of content

The badge next to an entry in the sidebar says what kind of content it provides.

| Badge | What the page does |
|---|---|
| Concept | Introduces the ideas as they're needed, and shows them in context of the workshop's real files or output. |
| Hands-on | Builds part of the profile or the policy in small iterations. Each iteration is one change, one command, what you see, and why. |
| Act | An agent interaction. We gather our files, launch the agent, and reason about what came back and what Box decided. |

Each hands-on and act page starts with a collapsed block called "your files at this point". It holds the complete files, so if you get lost you can paste them into your editor and carry on.

### The six acts

<div class="aib-acts-1">

| Act | Part | Where the decision is made |
|---|---|---|
| token-scope | 1 | Only in the API token's scope. Claude Code uses Cloudflare's MCP server with no box. |
| opaque-execute | 2 | In the `box`, but Box sees only that `execute` was called, not what the script did. |
| deny-execute | 3 | A policy rule refuses `execute` by name. |
| tool-allowlist | 4 | An allow-list of tool names, with one tool per API operation. |
| argument-rules | 4 | A rule on one tool's arguments: the tool may run on one account only. |
| request-rules | 5 | A rule on each HTTP request at the box's egress gateway. The agent's script runs inside the box. |

</div>

What each act shows is on [the story](/start/story/) page.

### Commands and files

Every step is one command for you to type, and every flag is explained under it. The Box profile and the policy files are written out by you, one setting or one rule at a time, starting from the smallest file that runs.

Most steps are checked with a **free check**: the command runs with an invalid model key, so Claude Code connects its MCP server and stops at its first model call. Nothing is billed. The acts themselves are real runs, which cost money; each act page says what one run cost when it was measured.

## How long each part takes

How long each act took on the clock (from [Measurements](/results/measurements/)) - excluding reading time:

<div class="aib-acts-3">

| Part | Pages | Act | Wall time of one run, as measured |
|---|---|---|---|
| 1 | 2 | token-scope | 10 s (allowed task), 13 s (logs task); no box, Claude Code 2.1.325 |
| 2 | 5 | opaque-execute | 22 s (logs task) |
| 3 | 2 | deny-execute | 17 s (logs task) |
| 4 | 4 | tool-allowlist, argument-rules | 75 s to 85 s per run; most of it is Box preparing the server's 3,053 tools before the agent may use them |

The times for the five boxed acts come from local box builds before a released Box filled early gaps, with Claude Code 2.1.330. [Builds and gaps](/results/builds-and-gaps/) explains any local builds used at the time of writing.

## What to remember

- One problem, solved in five parts; six acts are the hands-on moments.
- Two perspectives on every concept and act page: the security engineer's and the developer's.
- Concepts arrive when the story needs them, one per page.
- Hands-on means you type every command and write every file.
- Every number in the workshop was measured, and says where it came from. Anything not checked says "not checked".
