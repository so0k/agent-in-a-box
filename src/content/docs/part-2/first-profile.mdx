The picture is the one from the previous page: the box, the agent's sandbox inside it, and the trusted process with the box CLI and Box Core, the stand-in secrets and the egress gateway. This page builds two of those pieces in practice: the box CLI and Box Core, which you drive with `box run`, and the contained filesystem view, which your profile decides.

## The words this page uses

A **profile** is a folder in your Box home, `$HOME/box-ws/profiles/<name>/`, whose `profile.toml` names **packs**, reusable pieces of profile such as `@box/claude`. The agent's folders that last between runs are its **storage**, and each `box run` gets a box ID and a run folder. In output on this workshop's pages your home folder is written as `~`; Box prints the full path.

## Create the profile

<Iteration n={1} title="Create the profile from the Claude Code pack">

**What we do.** Ask Box to write a profile named `ws` that runs Claude Code with the Anthropic API.

<Tabs>
<TabItem label="Interactive">

<Command what="Creates the profile ws from the Claude Code starter, with the model on the Anthropic API, and asks its questions.">

```sh
box profile create ws --with claude,anthropic
```

<Flag name="ws">The profile's name. It becomes the folder `$BOX_HOME/profiles/ws/`. We use a short name because you type it in every command.</Flag>
<Flag name="--with claude,anthropic">The packs to use. `claude` picks the Claude Code starter and its pack `@box/claude`. `anthropic` adds the model route `@box/anthropic` and answers the starter's question of where the model runs, so the Bedrock questions are skipped.</Flag>

</Command>

The questions were captured with the profile name `claude` (`box profile create claude --with anthropic`); the same command with `ws` was run only without a terminal. Box asks three questions, in two sections, then shows a review.

The first question, in the `[ Setup ]` section:

```text
Import your MCP servers from ~/.claude.json?

! Includes servers you add later and servers configured for each project this
  profile runs in.
! Local servers run in the box with keys from their settings and your environment.
! A server variable that names a library folder or runtime options can load code.
! If it points where the agent can write, the agent's code runs with the server's
  keys.
! Remote servers' hosts become reachable.
! Copied settings can expose keys to the agent, even for servers Box skips.

  [1] Yes
> [2] No (default)

↑↓ choose  ←→ questions  Tab sections  Enter  Esc exit  Ctrl+C exit
```

The second, still in `[ Setup ]`:

```text
Run the command hooks in your ~/.claude/settings.json that each run one shell script, such
as a formatter after an edit
! Choosing true lets the agent read each script that an imported hook runs, and
  runs each script with the agent's own policy.
! A hook is a convenience, not a guardrail: the agent can change its own settings
  during a run.
! Write a rule that must hold as Box policy.
  [1] Yes
> [2] No (default)
```

The third, in `[ Policy ]`:

```text
Which policy should the agent start with?
> [1] Open (default)
    The agent can run any command and reach any host on the internet, but not localhost.
  [2] Scoped
    The agent can run any command, and reaches only what your packs and profile allow, such as the model and package registries.
  [3] Locked
    The agent can read your project but not change it, the box's shell runs none of its own commands, and the agent reaches only what
    your packs and profile allow.
```

Our answers:

| Question | Our answer | Keys | Why |
|---|---|---|---|
| Import your MCP servers | No (the default) | Enter | The acts name their one MCP server themselves; imported servers would bring their hosts and keys into the box. |
| Run the command hooks | No (the default) | Enter | A hook is a convenience, not a guardrail; the rules go in Box policy. |
| Which policy | Locked | Down, Down, Enter | Read-only project, no shell commands, only the hosts of packs and profile: the closest to the default deny the workshop wants. |
| Save this profile? | `[1] Save profile` | Enter | |

The review in the `[ Review ]` section lists the name, the agent, the policy, the packs (`claude, anthropic, cargo, git, node, npm, pnpm, yarn`), the three file paths and the selected options. After you save, Box prints `box: Profile saved`, a summary that names the skipped tools and says `Put the key for api.anthropic.com in ANTHROPIC_API_KEY.`, and a menu with `Run`, `Edit` and `Exit`. Press Ctrl+C to leave the menu (Exit was not tried for this workshop).

</TabItem>

<Command what="Creates the profile ws from the Claude Code starter, with the model on the Anthropic API and the Locked policy, without asking.">

```sh

```

<Flag name="ws">The profile's name. It becomes the folder `$BOX_HOME/profiles/ws/`.</Flag>

<Flag name="--policy locked">The answer to the policy question. Without a terminal Box cannot ask, so this flag is required. The MCP and hooks questions need no flag: both default to no.</Flag>

</Command>

<Iteration n={2} title="Read what was written">

**What we see.** `profile.toml` holds only your choices:

```toml title="$HOME/box-ws/profiles/ws/profile.toml"
# Written by `box profile create`. Your values go here, and the packs hold the rest.
# `box profile show ws` prints what a run gets.
# For help from a coding agent, tell it: Run box help agent and follow it.
packs = ["@box/claude", "@box/anthropic", "@box/cargo", "@box/git", "@box/node", "@box/npm", "@box/pnpm", "@box/yarn"]
policies = ["policy.dw"]

# How much of your project the agent reaches: "none", "read", "write".
[project]
access = "read"

[options]
claude.host = "anthropic"
claude.import-mcp = "false"
claude.import-hooks = "false"
```

- **Lines 1 to 3:** comments from `box profile create`. They stay in every profile block on later pages, so `packs` is always line 4 and `policies` line 5.
- **`packs`:** the Claude Code pack, the Anthropic route, and six tool packs that `create` adds by default.
- **`policies`:** the policy files of this profile, in order. `policy.dw` is the copied starter.
- **`[project] access = "read"`:** written because we chose Locked. The agent can read the workspace but not change it.
- **`[options]`:** `claude.host` comes from `anthropic` in `--with`; the two `import` lines are our two No answers.

`policy.dw` is the Locked starter with a three-line header. It holds one rule, `dev_null`, which lets programs read and write `/dev/null`, and a commented-out example of how to let the box's shell run named commands. Every other permit of a run comes from what the packs and the profile declare. The next page shows the file in full.

**What we change.** One line: `packs` keeps only the Claude Code pack and the Anthropic route.

```toml title="$HOME/box-ws/profiles/ws/profile.toml" del={4} ins={5}
# Written by `box profile create`. Your values go here, and the packs hold the rest.
# `box profile show ws` prints what a run gets.
# For help from a coding agent, tell it: Run box help agent and follow it.
packs = ["@box/claude", "@box/anthropic", "@box/cargo", "@box/git", "@box/node", "@box/npm", "@box/pnpm", "@box/yarn"]

[options]
claude.host = "anthropic"
claude.import-mcp = "false"
claude.import-hooks = "false"
```

<Why>

`create` adds six tool packs by default (`cargo`, `git`, `node`, `npm`, `pnpm` and `yarn`, from the release's `resources/config.toml`). A tool pack whose program is on your `PATH` is live, and it brings that program and its package hosts into the box: for `git` the measured run got a `spawn_git` permit and a `[tool.git]` table (for the others this is inferred from the packs). The story wants Claude Code and the model only.

<Fragment slot="alternative">

Leaving the tool packs out at creation is not possible: `--tools ""` is refused with `box: error: unknown tool ""; known tools: bunx, cargo, gh, git, go, node, npm, npx, pnpm, pnpx, rg, uv, uvx, yarn`. So we cut the line by hand.

</Fragment>

</Why>

## Run Claude Code for real

Now give Claude Code a real start. We use a **free check**: a run that sets the model key to an invalid value for that one command. Claude Code starts, reaches its first model call, gets refused by Anthropic, and exits. Nothing is billed.

<Iteration n={4} title="The free check">

**The run.**

<Command what="Starts Claude Code in the box for one headless turn, with an invalid model key so nothing is billed.">

```sh
ANTHROPIC_API_KEY=sk-ant-preflight-invalid-key box run ws --no-banner -- --bare -p "Say hello." --max-turns 1 --model claude-sonnet-5-5 < /dev/null
```

<Flag name="ANTHROPIC_API_KEY=sk-ant-preflight-invalid-key">A `NAME=value` prefix changes the variable for this one command only. The value is not a real key, so the first model call fails and costs nothing. This check has no money cap of its own, so never drop the prefix from it.</Flag>
<Flag name="run ws">Runs the profile `ws`. The folder you are in (`~/leaderboard-ops`) becomes the run's project.</Flag>
<Flag name="--no-banner">Turns off Box's activity banner, the one-line status Box draws under the agent. Headless runs and short checks do not need it.</Flag>
<Flag name="--">Ends `box`'s own options. Everything after it goes to Claude Code unchanged.</Flag>
<Flag name="--bare">Claude Code's minimal mode: no hooks, plugins, auto-memory, CLAUDE.md discovery, or keychain reads; the key comes only from `ANTHROPIC_API_KEY`. Your own Claude Code set-up stays out. It does not remove the pack's system prompt, which Box passes as a flag.</Flag>
<Flag name='-p "Say hello."'>Headless mode: one task, then exit. A greeting needs no tools.</Flag>
<Flag name="--max-turns 1">Stop after one model turn: a hard stop.</Flag>
<Flag name="--model claude-sonnet-5-5">Pins the model, so every run in this workshop uses the same one.</Flag>
<Flag name="< /dev/null">Gives Claude Code empty input. Without it, a headless Claude Code waits 3 seconds for input and prints a warning.</Flag>

</Command>

**What we see.** Claude Code's answer, after Box's start-up lines:

<Expect>

```text
Invalid API key · Fix external API key
```

</Expect>

## The perspectives

<Seat who="security">
The profile holds what we chose, and the packs hold the rest. Two lines decide the most: `packs`, cut to the agent and the model, and the Locked `policy.dw`, which permits nothing beyond what the packs and the profile declare. The agent's sandbox reaches its binary, two storage folders and a read-only project. What the pack copies from a developer's own `~/.claude` is on the next page.
</Seat>
<Seat who="developer">
One command, three answers and one trimmed line give a profile that starts Claude Code and reaches the model. `box profile show` says what a run gets before you start one.
</Seat>

## What to remember

- **The profile:** `box profile create ws --with claude,anthropic`, answered No, No, Locked, writes `profile.toml` and `policy.dw` in `$BOX_HOME/profiles/ws/`.
- **The trim:** `packs = ["@box/claude", "@box/anthropic"]` on line 4; the tool packs come in by default and cannot be left out at creation.
- **The pack:** it brings `@box/base`, the storage folders, the binary's grants and the Anthropic route.
- **The check:** `box profile show ws` before a run, and the free check with an invalid key to start one for nothing.
