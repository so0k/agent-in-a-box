Nothing new is added to the picture on this page. It is about two pieces already in it: the **egress gateway**, which every network request from the box goes through, and the **stand-in secrets**, which the agent holds in place of the real values.

## Two ideas before the first run

**The egress gateway.** The agent's sandbox has no direct network access. Box sets proxy variables for the agent (`HTTPS_PROXY`, `HTTP_PROXY`, `NODE_USE_ENV_PROXY=1`), so its traffic goes to the egress gateway inside the trusted process. The gateway opens every connection itself. It decrypts HTTPS with a certificate authority Box makes for this box (given to the agent as `SSL_CERT_FILE` and `NODE_EXTRA_CA_CERTS`), so it can read each request. For each new connection it asks the policy engine to decide a `net:connect`, and for each request an `http:request`. It has no allow-list of its own: what the policy does not permit is refused. That is **default deny**.

**Stand-in secrets.** Box can bind a credential to a set of hosts. The real value stays in the trusted process. The agent gets a **stand-in** (Box's design notes call it a phantom): a random value of the same shape, in the same variable. When the agent sends a permitted request to a bound host, the gateway replaces the stand-in with the real value on the way out. The agent can use the key. It cannot read it, print it or send it anywhere else.

These are from the Box design pages (`docs/design/architecture.md`, `docs/design/credentials.md`); the variable names were measured in this workshop's research by running `/usr/bin/env` as the boxed agent.

ANTHROPIC_API_KEY=sk-ant-preflight-invalid-key box run ws --no-banner -- --bare -p "Say hello." \

<Flag name="--model claude-sonnet-5-5">The pinned model.</Flag>
<Flag name="< /dev/null">Empty input, so Claude Code does not wait for it.</Flag>

</Command>

<Flag name="ws">Only this profile's runs. Without it, every profile's runs are listed.</Flag>

```sh

```

<Flag name="runs history">Reads the run's decision history: one row per decision, with the time, the result, the action, the resource, the rule that decided and the reason.</Flag>
<Flag name="<the newest BOX ID>">Replace with the ID, for example `b-e4d0f0dc5f9bfc35`. Type it without the angle brackets.</Flag>

</Command>

**What we see** (the CLI separates the columns with tabs):

<Expect variant="refuse">

```text
TIME (UTC)                      RESULT     ACTION       RESOURCE               RULE           REASON
2026-11-22T08:28:58.260432000Z  installed  policy       policy.dw              -              -
2026-11-22T08:28:58.712931000Z  deny       net:connect  api.anthropic.com:443  <default-deny> no permit matched
```

</Expect>

Two lessons in two rows:

1. The `ANTHROPIC_API_KEY` you exported in set-up did not reach the agent. The agent inherits nothing from your shell, so Claude Code had no key at all, and said "Not logged in".
2. Even with a key, Claude Code could not reach the model. The gateway refused the connection to `api.anthropic.com` on port 443, because no rule permits it. `<default-deny>` in the RULE column means exactly that.

The first row, `installed policy`, is the run's `policy.dw` being loaded. Box writes one even though the profile names no policy file: it holds the rules Box generates from the profile (Part 3 looks inside).

<Why title="Why not just pass the key through">
The tempting fix is one line in `[agent.env]`: `ANTHROPIC_API_KEY = { from = "env:ANTHROPIC_API_KEY" }`. It would hand the **real** key to the agent, and it would still leave the host closed. Not run in this workshop. (Box refuses a `from` for a variable that a route reads as a credential, so once the next iteration is in place, this line would be an error anyway.)
</Why>

</Iteration>

<Iteration n={2} title="A route with a stand-in">

**What we add.** A credentialed route for the Anthropic API.

```toml title="$HOME/box-ws/profiles/ws/profile.toml" ins={16-20}
packs = ["@box/base"]

[project]
access = "read"

[storage]
directories = ["config", "tmp"]

[agent]
command = ["${{ home }}/.local/bin/claude", { slot = "agent-args" }]

[agent.env]
CLAUDE_CONFIG_DIR = "${{ storage.config }}"
CLAUDE_CODE_TMPDIR = "${{ storage.tmp }}"

[egress.anthropic]
destinations = ["api.anthropic.com"]
secret.ref = "env://ANTHROPIC_API_KEY"
secret.header = "x-api-key"
secret.phantom_prefix = "sk-ant-"
```

Each line, in order:

- `[egress.anthropic]` declares a **route**: hosts the box may reach. `anthropic` is the route's name; Box uses it in the names of the rules it writes.
- `destinations = ["api.anthropic.com"]` is the host. Box writes two permits for it: `route_anthropic_connect` (`net:connect` to the host on port 443) and `route_anthropic_request` (every `http:request` to the host).
- `secret.ref = "env://ANTHROPIC_API_KEY"` names where the real value comes from: the variable `ANTHROPIC_API_KEY` in the shell that runs `box run`. Box reads it once, at start. The agent then finds a stand-in in its own `ANTHROPIC_API_KEY`.
- `secret.header = "x-api-key"` is the header the gateway writes the real key into. Anthropic's API reads its key from `x-api-key`. The default is `Authorization`.
- `secret.phantom_prefix = "sk-ant-"` makes the stand-in start like an Anthropic key: `sk-ant-` plus 64 random hex characters, so Claude Code accepts it as one. Without the line the stand-in starts with Box's default prefix, `strands_box_`; whether Claude Code would accept that was not checked.

**The run.** The same free check.

**What we see.** Claude Code now prints:

<Expect>

```text
Invalid API key · Fix external API key
```

</Expect>

That is progress. The request reached Anthropic with the swapped key, and Anthropic refused it, because the key in your shell for this command is the invalid one. The history shows the path (time column left out):

<Expect variant="permit">

```text
installed  policy        policy.dw                                                 -
permit     net:connect   api.anthropic.com:443                                     route_anthropic_connect
permit     http:request  api.anthropic.com:443/api/claude_code/settings            route_anthropic_request
permit     http:request  api.anthropic.com:443/api/claude_code/policy_limits       route_anthropic_request
permit     http:request  api.anthropic.com:443/api/eval/sdk-<id>                   route_anthropic_request
permit     http:request  api.anthropic.com:443/v1/messages                         route_anthropic_request
permit     http:request  api.anthropic.com:443/api/claude_code/organizations/metrics_enabled  route_anthropic_request
permit     http:request  api.anthropic.com:443/api/event_logging/v2/batch          route_anthropic_request
deny       net:connect   http-intake.logs.us5.datadoghq.com:443                    <default-deny>
```

</Expect>

There are more `net:connect` rows than shown. `/v1/messages` is the model call. With the real key in your shell (the same command without the prefix), Claude Code answers the prompt.

<Why>
The real key never enters the agent's process, and it can only travel to the one host it is bound to. A prompt that tells the agent to print its key prints a stand-in that is useless anywhere else.

<Fragment slot="alternative">
`packs = ["@box/base", "@box/anthropic"]`. The shipped `@box/anthropic` pack declares exactly this route: `box profile show ws --full` printed the same `[egress.anthropic]` table and the same two rules. We write it out so you can see it.
</Fragment>
</Why>

One limit to know. The gateway cannot tell which process in the box sent a request, so every process in a box can use every credential route (`docs/user/egress.md`). A route protects the key's value, not who may use it.

</Iteration>

<Iteration n={4} title="Quiet the agent's own traffic">

The history in iteration 2 shows more than the task needs: Claude Code's usage reporting (`event_logging`, `metrics_enabled`) and a refused Datadog host.

**What we add.** Two of Claude Code's own variables.

```toml title="$HOME/box-ws/profiles/ws/profile.toml" ins={15-16}
packs = ["@box/base"]

[project]
access = "read"

[storage]
directories = ["config", "tmp"]

[agent]
command = ["${{ home }}/.local/bin/claude", { slot = "agent-args" }]

[agent.env]
CLAUDE_CONFIG_DIR = "${{ storage.config }}"
CLAUDE_CODE_TMPDIR = "${{ storage.tmp }}"
CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC = "1"
DISABLE_AUTOUPDATER = "1"

[egress.anthropic]
destinations = ["api.anthropic.com"]
secret.ref = "env://ANTHROPIC_API_KEY"
secret.header = "x-api-key"
secret.phantom_prefix = "sk-ant-"
```

- `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC = "1"` turns off Claude Code's non-essential network traffic, such as usage reporting.
- `DISABLE_AUTOUPDATER = "1"` stops Claude Code from trying to update itself from inside the box.

**The run.** The same free check. **What we see:** the history now holds only the `settings`, `policy_limits` and `/v1/messages` requests to `api.anthropic.com`, and no Datadog row.

<Why>
The records should show what the task needs and nothing else, so a reader of them can spot the unusual request. And no usage data leaves the box.

<Fragment slot="alternative">
Leave them out. Default deny still refuses the Datadog host, but the event-logging calls to `api.anthropic.com` pass, because the route admits the whole host.
</Fragment>
</Why>

</Iteration>

## "Detected a custom API key": the question Claude Code asks

Every check on this page is headless. When you run Claude Code in the box **interactively** (the opaque-execute act does), it asks a question on its first screen:

```text title="Claude Code, interactive, in the box (line breaks approximate)"
Detected a custom API key in your environment

ANTHROPIC_API_KEY: sk-ant-...1031a80502699ab53f77

Do you want to use this API key?
  Yes
❯ No (recommended)
```

- **Why it asks.** Claude Code found `ANTHROPIC_API_KEY` in its environment, and asks before it uses a key it did not set up itself.
- **What it shows.** The last 20 characters of the key. In the box these are the end of Box's **stand-in**, not of your key. The example above is from a real check; your characters will differ.
- **What to answer.** Press the Up arrow, then Enter, to choose **Yes**. The default, No, sends Claude Code to its login flow, which cannot work here.
- **Why it asks every run.** Claude Code remembers its answers in its configuration folder, which is in the box's storage, so the theme, the notes and the folder-trust question are asked once. But the stand-in is new on every run, so to Claude Code it is a new key each time (a gap, listed in [Builds and gaps](/results/builds-and-gaps/)).

Compare the token-scope act, without a box: there the 20 characters are the end of your **real** key. Do not show that screen on a projector.

## The same move for the Cloudflare tokens

The model key is one of the three secrets from set-up. The two Cloudflare tokens get the same treatment, in two places later on:

| Secret | Who uses it | Where it is declared | Page |
|---|---|---|---|
| `CLOUDFLARE_MCP_TOKEN` | Claude Code, to talk to Cloudflare's MCP server | in the `[mcp.cloudflare]` table, with the same `secret.ref = "env://..."` line | [MCP through the broker](/part-2/mcp-through-the-broker/) |
| `CLOUDFLARE_API_TOKEN` | the scripts of the local exec proxy, calling the Cloudflare API directly | in a route `[egress.cloudflare-api]` | [Network rules for each API request](/part-5/egress-policy/) |

Why the MCP token does not get a plain route here: a route would only open the host. The `[mcp.cloudflare]` table also makes Box **recognise** the traffic as MCP and decide each tool call, which is the next page. Without a `phantom_prefix`, a Cloudflare stand-in starts with Box's default prefix: `strands_box_` plus 64 hex characters (measured in this workshop's research).

Both Cloudflare tokens are deliberately broad: they can read the leaderboard app's logs and delete its Worker. So when something is refused later, the refusal is Box's, not Cloudflare's.

## The two seats

<Seat who="security">
The real model key is out of the agent's reach, and bound to one host. Every connection the agent makes is now a decision you can read with `box runs history`, including the ones nothing permits. What a route does **not** give you: any say over which paths on the host are used. The route admits all of `api.anthropic.com`.
</Seat>
<Seat who="developer">
Claude Code reaches its model, with the key you already have in your shell. Nothing about how you talk to it changes, except one extra Yes on the key question in interactive runs. The two variables in iteration 4 cost nothing.
</Seat>

## What to remember

- The agent has no network of its own. Every request goes through the **egress gateway**, which asks the policy engine about each connection and each request. Nothing permitted means refused.
- A **route** (`[egress.<name>]`) opens hosts. With `secret.*` it also binds a credential: the agent holds a **stand-in**, the gateway swaps in the real value for those hosts only.
- `box runs list <profile>` finds a run; `box runs history <box ID>` shows what Box decided in it, and which rule decided.
- A missing secret variable stops the run before the agent starts.
