Nothing new is added to the picture on this page. It is about two pieces already in it: the **egress gateway**, which every network request from the box goes through, and the **stand-in secrets**, which the agent holds in place of the real values.

## Two ideas before the first run

**The egress gateway.** The agent's sandbox has no direct network access. Box sets proxy variables for the agent (`HTTPS_PROXY`, `HTTP_PROXY`, `NODE_USE_ENV_PROXY=1`), so its traffic goes to the egress gateway inside the trusted process. The gateway opens every connection itself. It decrypts HTTPS with a certificate authority Box makes for this box (given to the agent as `SSL_CERT_FILE` and `NODE_EXTRA_CA_CERTS`), so it can read each request. For each new connection it asks the policy engine to decide a `net:connect`, and for each request an `http:request`. It has no allow-list of its own: what the policy does not permit is refused. That is **default deny**.

**Stand-in secrets.** Box can bind a credential to a set of hosts. The real value stays in the trusted process. The agent gets a **stand-in** (Box's design notes call it a phantom): a random value of the same shape, in the same variable. When the agent sends a permitted request to a bound host, the gateway replaces the stand-in with the real value on the way out. The agent can use the key. It cannot read it, print it or send it anywhere else.

These are from the Box design pages (`docs/design/architecture.md`, `docs/design/credentials.md`); the variable names were measured in this workshop's research by running `/usr/bin/env` as the boxed agent.

**What we see.** The output is long. In the `# box.toml` part is the route that `@box/anthropic` declares, and in the `# policy.dw` part, after the starter's text, the two rules Box writes for it. Copied on Box 0.3.0, 2026-11-24, from the same command with the next page's `[mcp.cloudflare]` table already in the profile (these lines come from the pack, so they should not depend on it; inferred):

```toml title="Part of box profile show ws --full: # box.toml"
[egress.anthropic]
destinations = ["api.anthropic.com"]

[egress.anthropic.secret]
header = "x-api-key"
phantom_prefix = "sk-ant-"
ref = "env://ANTHROPIC_API_KEY"
```

```text title="Part of box profile show ws --full: # policy.dw"
@id("route_anthropic_connect") permit (principal, action == Box::Action::"net:connect", resource) when { (context.input.host == "api.anthropic.com" && context.input.port == 443) };
@id("route_anthropic_request") permit (principal, action == Box::Action::"http:request", resource) when { context.input.host == "api.anthropic.com" };
```

The pack's lines, in order:

- `[egress.anthropic]` declares a **route**: hosts the box may reach. `anthropic` is the route's name; Box uses it in the names of the rules it writes.
- `destinations = ["api.anthropic.com"]` is the host. Box writes two permits for it: `route_anthropic_connect` (`net:connect` to the host on port 443) and `route_anthropic_request` (every `http:request` to the host).
- `[egress.anthropic.secret]` holds the credential. In a profile you would write the same keys as `secret.ref`, `secret.header` and `secret.phantom_prefix` inside `[egress.anthropic]`; TOML reads both forms the same way.
- `ref = "env://ANTHROPIC_API_KEY"` names where the real value comes from: the variable `ANTHROPIC_API_KEY` in the shell that runs `box run`. Box reads it once, at start. The agent then finds a stand-in in its own `ANTHROPIC_API_KEY`.
- `header = "x-api-key"` is the header the gateway writes the real key into. Anthropic's API reads its key from `x-api-key`. The default is `Authorization`.
- `phantom_prefix = "sk-ant-"` makes the stand-in start like an Anthropic key: `sk-ant-` plus 64 random hex characters, so Claude Code accepts it as one. Without the line the stand-in starts with Box's default prefix, `strands_box_`; whether Claude Code would accept that was not checked.

<Why>
The real key never enters the agent's process, and it can only travel to the one host it is bound to. A prompt that tells the agent to print its key prints a stand-in that is useless anywhere else.

<Fragment slot="alternative">
Write the route by hand in `profile.toml` instead of taking it from `@box/anthropic`. An earlier version of this workshop did: its hand-written `[egress.anthropic]` table gave the same table and the same two rules in `box profile show ws --full` (measured).
</Fragment>
</Why>

<Why title="Why not just pass the key through">
The tempting alternative is one line in `[agent.env]`: `ANTHROPIC_API_KEY = { from = "env:ANTHROPIC_API_KEY" }`. It would hand the **real** key to the agent. Not run in this workshop. (Box refuses a `from` for a variable that a route reads as a credential, so with the pack's route in place this line would be an error anyway.)
</Why>

One limit to know. The gateway cannot tell which process in the box sent a request, so every process in a box can use every credential route (`docs/user/egress.md`). A route protects the key's value, not who may use it.

## "Detected a custom API key": the question Claude Code asks

<Aside type="note" title="Not run for this workshop">
Interactive mode was not run for this workshop. The screen below was measured earlier with the hand-written profile, on an earlier local build. With your own `~/.claude.json`, the pack may bring your onboarding answers in (`claude.import-app-state`), so you may see fewer screens (inferred, not checked).
</Aside>

Every check on this page is headless. When you run Claude Code in the box **interactively** (the opaque-execute act does), it asks a question on its first screen:

```text title="Claude Code, interactive, in the box (line breaks approximate)"
Detected a custom API key in your environment

ANTHROPIC_API_KEY: sk-ant-...1031a80502699ab53f77

Do you want to use this API key?
  Yes
❯ No (recommended)
```

- **Why it asks.** Claude Code found `ANTHROPIC_API_KEY` in its environment, and asks before it uses a key it did not set up itself.
- **What it shows.** The last 20 characters of the key. In the box these are the end of Box's **stand-in**, not of your key. The example above is from a real check; your characters will differ.
- **What to answer.** Press the Up arrow, then Enter, to choose **Yes**. The default, No, sends Claude Code to its login flow, which cannot work here.
- **Why it asks every run.** Claude Code remembers its answers in its configuration folder, which is in the box's storage, so the theme, the notes and the folder-trust question are asked once. But the stand-in is new on every run, so to Claude Code it is a new key each time (a gap, listed in [Builds and gaps](/results/builds-and-gaps/)).

Compare the token-scope act, without a box: there the 20 characters are the end of your **real** key. Do not show that screen on a projector.

## The same move for the Cloudflare tokens

The model key is one of the three secrets from set-up. The two Cloudflare tokens get the same treatment, in two places later on:

| Secret | Who uses it | Where it is declared | Page |
|---|---|---|---|
| `CLOUDFLARE_MCP_TOKEN` | Claude Code, to talk to Cloudflare's MCP server | in the `[mcp.cloudflare]` table, with the same `secret.ref = "env://..."` line | [MCP through the broker](/part-2/mcp-through-the-broker/) |
| `CLOUDFLARE_API_TOKEN` | the scripts of the local exec proxy, calling the Cloudflare API directly | in a route `[egress.cloudflare-api]` | [Network rules for each API request](/part-5/egress-policy/) |

Why the MCP token does not get a plain route here: a route would only open the host. The `[mcp.cloudflare]` table also makes Box **recognise** the traffic as MCP and decide each tool call, which is the next page. Without a `phantom_prefix`, a Cloudflare stand-in starts with Box's default prefix: `strands_box_` plus 64 hex characters (measured in this workshop's research).

The agent gets only what the profile and its packs pass in. The Claude Code pack passes some of Claude Code's own behaviour variables from your shell (`claude.import-env`), but not the key: Box gives the agent a stand-in. The tokens are passed the same way, through the tables that name them.

Both Cloudflare tokens are deliberately broad: they can read the leaderboard app's logs and delete its Worker. So when something is refused later, the refusal is Box's, not Cloudflare's.

## The two seats

<Seat who="security">
The real model key is out of the agent's reach, and bound to one host. Every connection the agent makes is now a decision you can read with `box runs history`, including the ones nothing permits. What a route does **not** give you: any say over which paths on the host are used. The route admits all of `api.anthropic.com`.
</Seat>
<Seat who="developer">
Claude Code reaches its model, with the key you already have in your shell. Nothing about how you talk to it changes, except one extra Yes on the key question in interactive runs. The variable in iteration 4 costs nothing.
</Seat>

## What to remember

- The agent has no network of its own. Every request goes through the **egress gateway**, which asks the policy engine about each connection and each request. Nothing permitted means refused.
- A **route** (`[egress.<name>]`) opens hosts. With `secret.*` it also binds a credential: the agent holds a **stand-in**, the gateway swaps in the real value for those hosts only. The `@box/anthropic` pack brings the route for the model.
- `box runs list <profile>` finds a run; `box runs history <box ID>` shows what Box decided in it, and which rule decided.
- A missing secret variable stops the run before the agent starts.
