<PartProgress current="part-1/token-scope" />

In this act the developer gets what they asked for: Claude Code with Cloudflare's MCP server and a token, and nothing in between. You will understand every flag the workshop passes to Claude Code, how the token reaches the server, and what comes back when the agent is asked for the logs. Every later act is measured against this one.

## Where we are in the story

The team runs the workshop progress tracker on Cloudflare. The developer wants a coding agent to help operate it: list the Workers, check the current deployment, look into a problem. The security engineer has written down that the agent must not read the Worker's logs, because they hold attendee names and email addresses. So far nothing enforces that. This act shows what happens without enforcement.

<Pieces stage={1} highlight="token-scope" />

The highlighted path is the whole story of the token-scope act. Claude Code holds the real Cloudflare token, sends it to the vendor's server, and the server reads the logs through the Cloudflare API.

<CatchUp>

You need the shell from [Set-up](/start/setup/): the exports of `PATH`, `BOX_HOME`, `BOX_TELEMETRY` and the three secrets, and the current folder `$HOME/leaderboard-ops`. No Box profile exists yet. The one workspace file:

```json title="$HOME/leaderboard-ops/cloudflare-code-mode.json"
{
  "mcpServers": {
    "cloudflare": {
      "type": "http",
      "url": "https://mcp.cloudflare.com/mcp",
      "headers": { "Authorization": "Bearer ${CLOUDFLARE_MCP_TOKEN}" }
    }
  }
}
```

</CatchUp>

## How the token reaches the server

The file above names one MCP server, `cloudflare`, of type `http`, at Cloudflare's code mode URL. It holds no secret. `${CLOUDFLARE_MCP_TOKEN}` is a placeholder that Claude Code fills in from its own environment when it connects.

In this act Claude Code inherits the environment of your shell, where [Set-up](/start/setup/) exported `CLOUDFLARE_MCP_TOKEN` from the keychain. So the header Claude Code sends to `mcp.cloudflare.com` carries the **real** token. The server then uses that token for every API request it makes on Cloudflare's side.

The same file, unchanged, works inside the box in Part 2. There the variable holds a stand-in, and Box swaps in the real token on the way out.

## Iterations

<Iteration n={1} title="A throwaway configuration for Claude Code">

**What we add.** An empty folder that Claude Code will use as its whole configuration in this act.

<Command what="Creates an empty folder for Claude Code's settings, sessions and transcripts in this act.">

```sh
mkdir -p "$HOME/leaderboard-ops-claude-token-scope"
```

<Flag name="-p">Creates the folder, and does nothing if it already exists.</Flag>

</Command>

**What we see.** Nothing. The folder is empty until Claude Code first runs.

<Why>

Every command below sets `CLAUDE_CONFIG_DIR` to this folder. Claude Code then reads and writes its settings, `.claude.json`, sessions and transcripts here, instead of in your own `~/.claude`. Your own configuration, memory, hooks and MCP servers stay out of the act, and nothing from the act lands in your configuration.

<Fragment slot="alternative">

Leave `CLAUDE_CONFIG_DIR` out and Claude Code uses `~/.claude`: your own settings and servers could change what the agent does, and the act's transcripts, which will hold log lines, would stay in your configuration.

</Fragment>

</Why>

</Iteration>

<Iteration n={2} title="A free check: does the server connect?">

**What we add.** Nothing to a file. We run Claude Code once with an invalid model key, so it connects the MCP server and stops at its first model call. Nothing is billed.

<Command what="Starts Claude Code headless with the code mode server, an invalid API key and the throwaway configuration, and writes its event stream to a file.">

```sh
ANTHROPIC_API_KEY=sk-ant-preflight-invalid-key CLAUDE_CONFIG_DIR="$HOME/leaderboard-ops-claude-token-scope" \
  claude --bare --strict-mcp-config --mcp-config cloudflare-code-mode.json --tools "" \
  --allowedTools mcp__cloudflare --model claude-sonnet-5-5 --max-turns 10 --max-budget-usd 0.25 \
  -p "Say hello." --output-format stream-json --verbose < /dev/null > token-scope-check.jsonl
```

<Flag name="ANTHROPIC_API_KEY=sk-ant-preflight-invalid-key">A `VAR=value command` prefix changes the variable for this one command only. With this invalid key Anthropic answers the first model call with `401` and Claude Code stops. Leave it out and the run uses your real key and is billed.</Flag>
<Flag name={'CLAUDE_CONFIG_DIR="$HOME/leaderboard-ops-claude-token-scope"'}>Claude Code's configuration folder for this command: the empty folder from iteration 1, not `~/.claude`.</Flag>
<Flag name="--bare">Minimal mode: no hooks, no plugin sync, no auto-memory, no CLAUDE.md discovery, no keychain or OAuth reads; the model key comes only from `ANTHROPIC_API_KEY` (`claude --help`, 2.1.330). Chosen so that nothing of your own Claude Code set-up takes part. Part 4 replaces it with `--setting-sources ""`, because `--bare` also removes the tool search tool.</Flag>
<Flag name="--strict-mcp-config">Use only the MCP servers named in `--mcp-config`. Without it Claude Code also loads servers from your user, project and plugin configuration.</Flag>
<Flag name="--mcp-config cloudflare-code-mode.json">The act's one MCP server, from the workspace file. A file keeps the token out of the command line: the file holds only the placeholder. The alternative, an inline JSON string, works but is hard to read.</Flag>
<Flag name={'--tools ""'}>No built-in tools: no Bash, no Read, no Edit. The agent's only tools are the server's, so the act shows what the server alone can do. Leave it out and the agent could also run shell commands on your machine.</Flag>
<Flag name="--allowedTools mcp__cloudflare">Pre-approves every tool of the `cloudflare` server. A headless run cannot answer a permission question, so without this every tool call would be refused by Claude Code itself. A narrower choice is one tool, for example `mcp__cloudflare__execute`.</Flag>
<Flag name="--model claude-sonnet-5-5">Pins the model, so the numbers of all six acts compare. An alias such as `sonnet` moves when a new model ships.</Flag>
<Flag name="--max-turns 10">Stops after 10 model turns: a hard stop in every run. `claude --help` does not list this flag; it worked in every headless run here.</Flag>
<Flag name="--max-budget-usd 0.25">Stops the run when it has cost 0.25 USD. It works only with `-p`.</Flag>
<Flag name={'-p "Say hello."'}>Headless: one task, then exit. The free check needs no real task.</Flag>
<Flag name="--output-format stream-json">One JSON event per line instead of only the answer, so the tools offered, the turns, tokens and cost can be read afterwards.</Flag>
<Flag name="--verbose">Needed with `stream-json` in headless mode, so every event is written.</Flag>
<Flag name="< /dev/null">Gives Claude Code an empty standard input. Without it Claude Code waits 3 seconds and prints `Warning: no stdin data received in 3s`.</Flag>
<Flag name="> token-scope-check.jsonl">Writes the event stream to a file in the workspace. Error messages still go to the terminal.</Flag>

</Command>

**What we see.** The command exits with status 1. Open the file and look at its first line, the `init` event:

<Command what="Prints the first line of the event stream.">

```sh
head -1 token-scope-check.jsonl
```

<Flag name="-1">Only the first line: the event that lists the MCP servers and the tools Claude Code received.</Flag>

</Command>

<Expect>

In the first line (abridged; the event is one long line of JSON): `"mcp_servers":[{"name":"cloudflare","status":"connected"}]`, and five Cloudflare tools: `mcp__cloudflare__docs`, `mcp__cloudflare__execute`, `mcp__cloudflare__search`, `mcp__cloudflare__submit_feedback`, `mcp__cloudflare__whoami`. The last line of the file is the result: `Invalid API key · Fix external API key`, cost 0.

</Expect>

The throwaway folder now holds `.claude.json`, `backups/`, `plugins/`, `projects/` and `sessions/`: Claude Code's own state, written there and not in `~/.claude`.

<Why>

A free check proves the whole set-up, the token, the server and the flags, before you spend money. The workshop uses the same check at every step.

<Fragment slot="alternative">

Go straight to the real run: if the server fails to connect, you pay for model turns in which the agent has no Cloudflare tools.

</Fragment>

</Why>

</Iteration>

## Run the act

The two task sentences are the same in every act. The allowed one is what the developer needs; the logs one is what the security engineer wants refused.

<Prompt label="The allowed task">List the Workers on Cloudflare account 0123456789abcdef0123456789abcdef and summarise the current deployment of the Worker box-poc-workshop.</Prompt>

<Prompt label="The logs task">Show me the last hour of logs for the Cloudflare Worker box-poc-workshop on account 0123456789abcdef0123456789abcdef.</Prompt>

<Tabs syncKey="run-mode">
<TabItem label="Interactive">

<Command what="Starts Claude Code in the terminal with the code mode server and the throwaway configuration, asking before any tool that is not pre-approved.">

```sh
CLAUDE_CONFIG_DIR="$HOME/leaderboard-ops-claude-token-scope" claude --bare --strict-mcp-config \
  --mcp-config cloudflare-code-mode.json --tools "" --allowedTools mcp__cloudflare \
  --model claude-sonnet-5-5 --max-turns 10 --permission-mode manual
```

<Flag name="--permission-mode manual">Every tool that is not pre-approved asks you first. In an empty configuration Claude Code announced that auto mode is its default, which runs a classifier on tool calls; manual keeps the decision with the person. Other choices: `acceptEdits`, `auto`, `bypassPermissions`, `dontAsk`, `plan`.</Flag>

</Command>

The other flags are as in the free check. There is no `-p`, no `--max-budget-usd` (it works only headless) and no output file. Whether `--max-turns` holds in interactive mode was not checked.

In an empty configuration Claude Code asks four first-run questions, in this order:

| Screen | Answer |
|---|---|
| Theme picker | Enter (any theme). |
| `Detected a custom API key in your environment` with the last 20 characters of the key, and `No (recommended)` selected | Up arrow, Enter (Yes). No sends you to a login that cannot work here. In this act those 20 characters are the end of your **real** key: do not show this screen on a projector. |
| `Security notes` | Enter. |
| `Accessing workspace: ~/leaderboard-ops` with `No, exit` selected | Down arrow, Enter (Yes, I trust this folder). The default exits with `Claude Code didn't start because this folder isn't trusted.` |

Then the prompt appears. Type the allowed task, then the logs task.

</TabItem>
<TabItem label="Headless">

<Command what="Runs the logs task once, headless, with a budget cap, and writes the event stream to a file.">

```sh
CLAUDE_CONFIG_DIR="$HOME/leaderboard-ops-claude-token-scope" claude --bare --strict-mcp-config \
  --mcp-config cloudflare-code-mode.json --tools "" --allowedTools mcp__cloudflare \
  --model claude-sonnet-5-5 --max-turns 10 --max-budget-usd 0.25 \
  -p "Show me the last hour of logs for the Cloudflare Worker box-poc-workshop on account 0123456789abcdef0123456789abcdef." \
  --output-format stream-json --verbose < /dev/null > token-scope-logs.jsonl
```

<Flag name={'-p "Show me the last hour of logs ..."'}>The logs task. For the allowed task, put that sentence here and write to `token-scope-allowed.jsonl`.</Flag>

</Command>

Every other flag is as in the free check, without the invalid key: this run uses your real key and is billed. Read the answer with `less token-scope-logs.jsonl`; the last line is the result.

</TabItem>
</Tabs>

## What comes back

<Expect title="What you should see (measured 2026-11-24, Claude Code 2.1.331, headless)">

- **Allowed task:** done in 2 turns with 1 `execute`. The account has one Worker, `box-poc-workshop`; its current deployment is of 2026-11-24 05:09 UTC, and it has 5 deployments in all.
- **Logs task:** 1 `docs` call, 3 `search` calls, then 2 `execute` calls, 7 turns. The vendor's `search` found the observability query and its `execute` ran it on Cloudflare's side. The query covered 10:27 to 11:27 UTC, and that hour held 0 events, so the answer had no log lines.
- **Box decisions:** none. There is no box.

</Expect>

An earlier run, on 2026-11-14 with Claude Code 2.1.325, shows what a busier window holds. In its last hour the answer held two request lines, `GET /healthz` and `GET /api/workshop`. Over a 24-hour window the answer quoted a `session.step_advanced` event with an email address (`<redacted>`). What the log window holds depends on when you run it: attendee events with names and emails are there whenever attendees were active in that window.

<Seat who="security">

You see nothing, and nothing decided anything. The agent held a token that can read logs and delete Workers, and the only record of what it did is the transcript in the throwaway folder, which holds whatever log lines came back. Your constraint, "do not read the logs", existed only as a sentence. The next part puts a boundary around the agent so that there is something that can decide and record.

</Seat>

<Seat who="developer">

Both tasks work, quickly and cheaply: 2 turns and 0.0187 USD for the allowed task, 7 turns and 0.0756 USD for the logs. There was no friction at all, which is exactly the problem the security engineer has with it.

</Seat>

**Takeaway:** with a broad token and no boundary, the agent can do the forbidden task as easily as the allowed one, and nobody but the agent sees it.

## Clean up

The stream files and the throwaway configuration hold the transcript, including log lines with attendee data. Delete them.

<Command what="Deletes the act's throwaway Claude Code configuration and its stream files.">

```sh
rm -rf "$HOME/leaderboard-ops-claude-token-scope" token-scope-check.jsonl token-scope-logs.jsonl token-scope-allowed.jsonl
```

<Flag name="-rf">Removes the folder with everything in it, without asking. Check the path before you press Enter.</Flag>

</Command>

## What to remember

- `CLAUDE_CONFIG_DIR`, `--bare` and `--strict-mcp-config` keep your own Claude Code set-up out of every act.
- `--tools ""` leaves the agent only the server's tools; `--allowedTools` pre-approves them for headless runs.
- `--model`, `--max-turns` and `--max-budget-usd` make every run comparable and capped.
- With no box, the real token goes from your shell to the vendor's server, and the logs query runs.
